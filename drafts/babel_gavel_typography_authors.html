The Four Chambers

Each package is a distinct floor of the tower, holding its own craft and purpose.

Model

The core data structure for linguistic units. Holds the Token class (word + grammatical properties) and Sentence (collections of tokens). Everything else reads from and writes to these records.

Token · Sentence

Analysis

Syntactic analysis via SentenceAnalyzer. Tags words as Subject, Verb, Auxiliary, Negation, or defaults to Other when missing from the CSVs—so the pipeline never breaks.

Roles · Lookup · Fallback

Translation

Direct dictionary lookups. The Translator maps each token against the Dutch dictionary CSV and swaps the English word—keeping the original role. Unmatched words stay English.

Dictionary · Literal Swap

Rules

Grammatical restructuring. The RuleEngine reorders tokens by Dutch syntax patterns. Verb-Second is fully implemented; four further rules await completion.

How a Sentence Climbs the Tower

From English input to Dutch structure—one deliberate step at a time.

1

Entry Point

The application receives an English text string from the user via the console.

2

Sentence Analysis

SentenceAnalyzer cleans the input, splits it into words, and assigns each a grammatical role (Subject, Verb, Auxiliary, Negation, or Other).

3

Structure Revealed

The analyzed tokens and their roles are displayed so the journey is visible.

4

Literal Translation

Translator maps every token against the Dutch dictionary CSV. Roles travel with the words; unknown terms remain in English.

5

Direct Result

The word-for-word Dutch version is shown—still in English word order.

6

Rule Selection

The user chooses a grammar rule from the console prompt (currently Verb-Second is the complete path).

7

Rule Engine

RuleEngine reorders the tokens according to the chosen Dutch syntax pattern, using the roles as navigation beacons.

8

Final Rendering

The restructured Dutch sentence is printed—the ultimate output of the climb.

Elina · Interaction 1

Missing words in the analysis CSV

What I needed

Clarify how SentenceAnalyzer handles words that are missing from the analysis CSV lookup files.

What AI told me

Unlisted words receive a default or generic role (for example “Other”) so the pipeline continues without exceptions.

What I did with it

Noted the resilient design—unknown words still travel through translation and rules unharmed.

Elina · Interaction 2

Why translation stays separate from rules

What I needed

Understand why translation logic (Translator) is kept separate from syntax manipulation (RuleEngine).

What AI told me

Separation follows the Single Responsibility Principle: new grammar rules can be added without touching dictionary code.

What I did with it

Used the insight to write a clearer architectural summary and appreciate the modularity of the repository.

Matthew · Interaction 1

What each package does

What I needed

Understand what each of the four packages does and how they connect.

What AI told me

Model stores words and roles; Analyser assigns roles; Translator swaps English→Dutch; RuleEngine rearranges the translated tokens.

What I did with it

Walked the code myself to confirm how a sentence travels from input to final output.

Matthew · Interaction 2

Token roles and the RuleEngine

What I needed

Learn what a token’s role actually means and how RuleEngine uses it.

What AI told me

Roles come from word-list matching; the engine uses those roles to locate and move the correct tokens (for example Verb-Second).

What I did with it

Traced determineRole() and the Verb-Second implementation, and discovered the other four rules are still stubs.
